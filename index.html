Judged blind. Picked almost every time.

Evidence graph

Every sentence has a receipt.

Before any model writes a word, Tracetoon builds a small graph of your branch. It links every change in the diff back to the conversation that produced it:

  • your request
  • →
  • agent edit
  • →
  • hunk in the diff
  • →
  • commit sentence
  • →
  • test run
  • Credit goes to the right code. The brief names the function that owns each behavior and marks what's new and what only changed. It also flags code where a word like "always" would be wrong.
  • Validation comes from receipts. Tracetoon writes the Validation section from the test and build runs on the final code. The model never gets to type "all tests pass."
  • The why, not just the what. Plans, decisions and the original request come along with the code, so context coverage rose 5–7 points.

Embedded database

A graph database that fits in your pocket.

The graph runs on Relate, an open-source embedded graph database written in Rust. Tracetoon ships it compiled to WebAssembly inside the CLI, so there's nothing else to install.

  • No server, no setup. It runs inside the CLI on Linux, macOS and Windows, works offline, and builds a fresh graph for every PR.
  • Real queries, not guesswork. A few lines of Cypher answer questions like "which request led to this code?" and "did a test pass after the last edit?" Relate's BM25 fulltext index links each commit sentence to the code it describes.
  • Same evidence in, same brief out. Every fact traces back to a hunk and a session line, so you, or another agent, can audit any sentence.
0 tokensto build the graph and the evidence brief. It's a deterministic step, not a model call.
Cost savings

A sharp brief lets cheap workers check the work.

Without a map, an expensive model rereads your source to check its own claims, two or three times per PR. With the graph, that work is done once, before any model runs. Then:

  • One strong writer drafts from a 2–3K-token brief instead of the whole session history, and writes 7K tokens instead of 22K.
  • Two cheap reviewers (Haiku or Luna, at extra-high reasoning effort) check a short packet. That costs about 4¢ per PR on Claude and under 1¢ on Codex.
  • One edit pass. The reviewers' findings merge into a single list. There are no repeat review rounds and no forked subagents.
  • Claude, no graph $0.69
  • Claude + graph $0.41
  • Codex, no graph $0.32
  • Codex + graph $0.21

Fits your workflow

Just ask for a PR. It knows the house rules.

  • Nothing new to learn. Ask your agent for a PR, or let it run gh pr create as usual. Tracetoon writes the description, has it reviewed and creates the PR. Then it tells you what it did: the link, whether a comic is included, and any sessions it left out.
  • Your words stay yours. Anything you write in the PR, or edit on GitHub later, is kept on the next update.
  • Follows the house rules. Tracetoon reads each repo's AI policies, AGENTS.md, PR templates and contribution guides, and adds any disclosure the repo asks for. Where a repo's rules forbid images in PRs, the comic is left out automatically.
  • Private by default. Logs are read on your machine, and private paths and secrets are redacted from the evidence.
  • Easy to switch off. Run tracetoon off to turn it off everywhere or per repo, or set TRACETOON=0 for a single command.
Comics

And a comic nobody asked for. Everyone reads it.

Each PR can get a one-off comic: a joke about how the work really went, with characters, a format and an art style made up for that PR. It might be a gag strip, a before and after, a movie poster or an instruction manual. Your agent proofreads every word.

  • It's drawn with an image route you already have: the Codex CLI with a ChatGPT login, Antigravity, or an OpenAI or Gemini API key.
  • It respects the repo. Where contributing rules forbid images in PRs, Tracetoon skips the comic and tells you why.
  • It's your choice. Run tracetoon config set comic off and your PRs have no comic. Set it to always to ignore repo rules.

Under the hood

From session logs to a reviewed PR

  1. Find the sessionsTracetoon matches agent edits to lines in your diff, and asks you when a session is ambiguous.
  2. Build the graphtracetoon prepare turns the logs and git history into a redacted evidence brief, using 0 tokens.
  3. WriteOne strong model drafts 250–400 words and ties each fact to a row of the brief.
  4. CheckDeterministic checks run first, then two cheap reviewers. One edit pass applies their findings.
  5. PublishTracetoon creates the PR, adds the comic if the repo allows it, and tells you what it did.
How we measured (and what's not perfect yet)

The numbers come from prbench: 5 real PRs from Tracetoon's own development, each with its original agent session logs, and 5 drafts per PR for each setup. For each PR, a person wrote a fact sheet from the diff and the sessions. AI judges scored every draft against that fact sheet with a 10-item reviewer rubric. Claude runs used Opus 5.5 and Sonnet 5.5 as judges; Codex runs used Sol 6.1 and Terra 6.1. A head-to-head win counts only when both judges, each reading the pair in both orders, pick the same draft. Each comparison uses the same model with the graph and without it. All figures are from the shipped build (round 23).
